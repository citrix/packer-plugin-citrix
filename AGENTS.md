## 📋 Service Overview

**Purpose**: HashiCorp Packer plugin that automates Citrix App Layering (ELM — Enterprise Layer Manager) layer creation and revision workflows. It wraps the ELM SOAP API inside a Packer builder/provisioner so that standard Packer HCL templates can:

1. Call the ELM SOAP API to create a CE (Compositing Engine) VM in the customer hypervisor
2. Wait for the CE VM to come up (IP polling)
3. Connect to the CE VM via WinRM
4. Run Packer provisioners (install software, etc.) inside the CE VM
5. Trigger `ShutdownForFinalize` to finalize and publish the layer

**ELM** is the on-premises Citrix App Layering appliance. It exposes a SOAP API on port 443.  
**CE VM** is a temporary WinPE-based VM created by ELM to process layer operations.

## 🏗️ Internal Architecture

### Builder Pipeline (multistep)

```
Prepare() ← validates HCL2 config, selects communicator (WinRM only)
  ↓
Run():
  StepConnectElm       → ELM SOAP auth (captures cookie + Unidesk_token header)
  StepPreflightCheck   → verify referenced layers exist, target name not already taken
  StepCreateXxx        → call ELM SOAP API, get WorkTicketId + CE VM info
  StepWaitForIp        → poll ELM every N seconds until CE VM IP is assigned
  StepConnectCommunicator (WinRM) → connect to CE VM
  [User Provisioners run here]
  StepProvision        ← citrix-layerartifact provisioner
    └─ BlockFinalize loop: poll LayerIntegrity.txt, wait for all bits clear
    └─ ShutdownForFinalize.cmd: finalize and publish the layer to ELM
```

**State bag keys** (passed between steps):
| Key | Type | Set by |
|-----|------|--------|
| `elmclient` | `elmsoap.ApiSoap` | StepConnectElm |
| `COOKIE` | `string` | StepConnectElm |
| `UNIDESK_TOKEN` | `string` | StepConnectElm |
| `UNIDESK_URL` | `string` | StepConnectElm |
| `INSECURE_CONNECTION` | `bool` | StepConnectElm |
| `WORK_TICKET_ID` | `int64` | StepCreate/Revision |
| `instance_ip` | `string` | StepWaitForIp |
| `generated_data` | `map[string]any` | initialized in Builder.Run |

### Strategy Pattern

`BuilderStrategy` interface is implemented per operation type. Adding a new operation = add a new `*Strategy` struct; `Builder.Run()` stays unchanged.

```go
type BuilderStrategy interface {
    OperationSteps() []multistep.Step       // the one step that calls ELM
    OperationType() elmsoap.ApplayeringOperationType
    Artifact(state multistep.StateBag) *Artifact
}
```

`installer.go` registers the factory in the `dig` DI container:
```go
// main.go
container := dig.New()
applayering.Install(container)
// → container provides: func(*config.Config) BuilderStrategy
```

### Preflight Check Pattern

Each operation type has its own `OperationPreflightStrategy`:
- `CREATE_*`: verifies target layer name does **not** exist yet
- `REVISION_*`: verifies referenced layer + version **do** exist, target version name not taken
- `CONNECT_ONLY`: no-op preflight

### Provisioner Logic

`citrix-layerartifact` provisioner (`provisioner/citrix/applayering/provisioner.go`):

1. Reads `C:\Program Files\Unidesk\Uniservice\Log\LayerIntegrity.txt` (JSON)
2. Checks `BlockFinalize` bitmask — waits until all bits are cleared (reboots handled by WinRM reconnect). If `IC_RUNONCE` is set and `handle_run_once` is `false` (default), the provisioner logs a message and exits successfully — the user must handle RunOnce entries manually via the CE VM.
3. Calls `ShutdownForFinalize.cmd` to publish the layer version back to ELM

**BlockFinalize bits**:
| Bit | Value | Meaning |
|-----|-------|---------|
| `icBypass` | 1 | Bypass finalize |
| `icReboot` | 2 | Reboot pending |
| `icInstaller` | 4 | Installer running |
| `icNgen` | 8 | .NET NGEN in progress |
| `icRunOnce` | 16 | RunOnce pending |
| `icWinUpgrade` | 32 | Windows Upgrade pending |
| `icNgenNeeded` | 64 | NGEN needed |
| `icSmsCfgPresent` | 128 | SMS config present |
| `icFsLogix` | 256 | FSLogix pending |
| `icWemRsaKeyFile` | 512 | WEM RSA key file |
| `icDelTokens` | 1024 | Delete tokens pending |
| `icKmsDirMissing` | 2048 | KMS dir missing |
| `icKmsGpoMissing` | 4096 | KMS GPO missing |

## 🔑 ELM SOAP Client

### elm_client.go (auto-generated)
Generated via `gowsdl` from ELM's WSDL definition. **Do not edit manually.** ~13,000 lines.

Key interface: `ApiSoap` — all ELM operations go through this interface.

Key types generated:
- `ApplayeringOperation` / `ApplayeringOperationResult` — create layer ops
- `GetAllLayersResult` — list all layers
- `GetWorkTasks` / `WorkTaskResult` — poll CE VM status (IP, progress)

### soap_helpers.go (hand-written)
Helper functions layered on top of elm_client.go:

```go
// Operation type constants
type ApplayeringOperationType string
const (
    CREATE_APP_LAYER      ApplayeringOperationType = "CREATE_APP_LAYER"
    CREATE_PLATFORM_LAYER ApplayeringOperationType = "CREATE_PLATFORM_LAYER"
    REVISION_OS_LAYER     ApplayeringOperationType = "REVISION_OS_LAYER"
    REVISION_PLATFORM_LAYER ...
    REVISION_APP_LAYER    ...
)

// Layer lookup helpers (used by preflight + step implementations)
GetOsLayerRevisionId(client ApiSoap, layerName, versionName string) (int64, error)
GetPlatformLayerRevisionId(...)
GetPlatformLayerId(...)
GetAppLayerRevisionId(...)
```

### Authentication Flow

ELM uses a two-part session mechanism:
1. `Login` SOAP call → server sets `Set-Cookie: Unidesk=...` header
2. Subsequent calls must include `Cookie: Unidesk=...` AND `Unidesk_token: ...` header

`StepConnectElm` uses `HeaderCaptureTransport` (wraps `http.RoundTripper`) to capture both values from the login response and inject them into subsequent requests.


## ⚙️ HCL2 Configuration Summary

### Top-level fields (all operations)

| Field | Required | Notes |
|-------|----------|-------|
| `elm_server` | ✅ | ELM IP or hostname |
| `elm_username` | ✅ | ELM login username |
| `elm_password` | ✅ | Use HCL variable |
| `insecure_connection` | — | `true` for self-signed cert labs |
| `wait_for_ip_timeout` | — | Seconds, default 600 |
| `communicator` | — | Must be `"winrm"` (only type supported) |

### Operation blocks (exactly one must be present)

```
create_app_layer { ... }
create_platform_layer { ... }
revision_os_layer { ... }
revision_platform_layer { ... }
revision_app_layer { ... }
connect_only { ... }       ← debug only: does not call ELM, connects to existing CE VM
```

> For full per-operation parameter reference, see the docs-partials folder.

### Minimal create_app_layer example

```hcl
source "citrix-applayering" "my_app" {
  elm_server          = "your-elm-server.example.com"
  elm_username        = "Administrator"
  elm_password        = var.elm_password
  insecure_connection = true

  create_app_layer {
    os_layer_name                  = "Win10_OS"
    os_layer_version_name          = "v1.0"
    platform_layer_name            = "VMware_PF"
    platform_layer_version_name    = "pf_v1.0"
    layer_name                     = "MyApp"
    version_name                   = "v1.0"
    version_size_gb                = 10
    platform_connector_config_name = "VMwareConn"
    packaging_disk_file_name       = "MyApp_v1.0"
    icon_id                        = 196608
  }

  communicator   = "winrm"
  winrm_username = "Administrator"
  winrm_password = var.vm_password
}

build {
  sources = ["source.citrix-applayering.my_app"]
  provisioner "citrix-layerartifact" {}
}
```

## 🚨 Important Notes

### Communicator: WinRM Only
The builder only supports `winrm` as the communicator type. SSH support has not been implemented.  
If `communicator` is omitted it defaults to `winrm`; if set to anything else, `Prepare()` returns an error.

### elm_client.go Do Not Edit
`elm_client.go` is auto-generated from the ELM WSDL using `gowsdl`. The file header says `// Code generated by gowsdl DO NOT EDIT`. All helper logic goes in `soap_helpers.go`.

### CONNECT_ONLY is Debug-Only
The `connect_only` operation block does NOT call ELM to create a new CE VM. It connects to an already-running CE VM by specifying `work_ticket_id` directly. Use only for local debugging.

### insecure_connection Warning
`insecure_connection = false` (the secure default) generates a Packer warning telling users to ignore it if testing with self-signed certificates. This is intentional UX — the lab environments typically use self-signed certs and need `true`.

### Exactly One Operation Block
`builder.Prepare()` enforces that exactly one of the 6 operation blocks is non-nil. Multiple blocks → error.

### icon_id Must Be Specified Explicitly
`icon_id` is an optional field in `CreateAppConfig` and `CreatePlatformConfig`. It defaults to `196608`, but `builder.go:applyIconIdDefault()` emits a Packer **Warning** whenever `icon_id == 0` at the time of default application. Always set `icon_id = 196608` (or the desired value) explicitly in `create_app_layer { }` and `create_platform_layer { }` blocks to suppress the warning.

### shutdown_for_finalize Field Removed
The `shutdown_for_finalize` field no longer exists in the provisioner `Config` struct. The provisioner always runs the full BlockFinalize polling loop followed by `ShutdownForFinalize.cmd`. Do **not** add `shutdown_for_finalize` to `provisioner "citrix-layerartifact" {}` blocks — it will cause an `Unsupported argument` error.

### platform_layer is Optional in create_app_layer
`platform_layer_name` and `platform_layer_version_name` are both optional inside `create_app_layer { }`. Omitting them creates an app layer without a platform layer association. See `create_app_no_platform_finalize.pkr.hcl` for a working example.

### TimestampedUi
`common.TimestampedUi` wraps `packersdk.Ui` and prepends a `"2006-01-02 15:04:05.000"` millisecond-precision timestamp to every `Say` and `Sayf` call. Used in `Builder.Run()` to timestamp all builder log output.

### Windows-Only Build
This plugin targets **Windows only**. The output binary is `packer-plugin-citrix.exe`. SSH communicator support is not planned — WinRM is the only supported communicator. Do not attempt to cross-compile for Linux/macOS.
